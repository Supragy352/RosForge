## How RosForge Organizes a Workspace

When you open or create a workspace folder in RosForge, it creates and maintains a standard ROS 2 layout alongside a single metadata file:

```text
<workspace>/
├── .rosforge.json          # Canonical graph model, canvas positions, and file hashes
├── src/                    # Standard ROS 2 workspace source directory
│   ├── <py_pkg>/           # Generated ament_python package
│   │   ├── package.xml
│   │   ├── setup.py
│   │   ├── setup.cfg
│   │   ├── resource/<py_pkg>
│   │   ├── <py_pkg>/
│   │   │   ├── __init__.py
│   │   │   └── <node>.py
│   │   └── launch/*.launch.py
│   └── <cpp_pkg>/          # Generated ament_cmake package
│       ├── package.xml
│       ├── CMakeLists.txt
│       ├── src/<node>.cpp
│       └── launch/*.launch.py
├── build/                  # Created by `colcon build`
├── install/                # Created by `colcon build`
└── log/                    # Created by `colcon build`
```

Because RosForge emits standard ROS 2 packages under `src/`, your workspace builds cleanly with `colcon` both inside and outside RosForge—no proprietary runtime or lock-in.
